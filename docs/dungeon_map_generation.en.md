# How the dungeon map is made

*[Versione italiana](dungeon_map_generation.md)*

This document explains, step by step and with real examples, how WyrmDelve builds the ASCII map of a dungeon: from the rooms to the corridors, from the stairs to the entrances, all the way to the printed sheet. No programming knowledge is needed: whenever a technical term comes up, it is explained in plain words.

Every map in this document was generated by the program, not drawn by hand. You can make them again with the seeds given.

> The story of the dungeon (who built it, who lives there, what is in the rooms) has a document of its own: [story_generation_algorithm.en.md](story_generation_algorithm.en.md).

## 1. The path in short

When you run the program you see a bar with 10 steps. Each one matches a part of this document:

| Step | What happens | Chapter |
|---|---|---|
| 1. Settings | the seed is read (or made) | 2 |
| 2. Layered history | founders, ages and dwellers are chosen | story document |
| 3. Rooms and strata | how many rooms, where they go, their age and their shape | 3–8 |
| 4. Corridors and loops | the rooms of each level are joined, with loops | 9 |
| 5. Level connections and entrances | stairs, shafts, portals, entrances; then the dead ends are removed | 10–12 |
| 6. Secret and unusual paths | secret doors, hidden passages, water, cave-ins, steps | 13 |
| 7. Checking Jaquays' principles | the dungeon is checked against the rules | 14 |
| 8. Print format | paper and letter size are chosen | 16 |
| 9. Game master map | the full map is drawn and saved | 15 |
| 10. Players' map and key | the map without secrets is drawn and the key is written | 15 |

One idea runs through the whole program: the dungeon must be **"Xandered"**, that is, follow the principles Justin Alexander gathered in his *Xandering the Dungeon* series by studying Jennell Jaquays' dungeons. In plain words: **more than one way to get anywhere**, loops instead of dead ends, several entrances, several connections between levels, secrets and shortcuts. That way the players always have choices to make.

## 2. The seed: the dungeon's recipe

Every dungeon has a **seed**, a sort of recipe written on one line. With the same seed the program always makes the very same dungeon, on any computer.

Example: `3-21-2-4-CDK-000F62`

| Part | Value | Meaning |
|---|---|---|
| `3` | levels | 3 main levels |
| `21` | rooms | 21 rooms in all |
| `2` | entrances | 2 entrances from outside |
| `4` | secrets | 4 secret doors and secret passages |
| `CDK` | types | level 1 = **C** Tower, level 2 = **D** Castle, level 3 = **K** Underdark (a single letter = every level of that type) |
| `000F62` | code | 6 symbols acting as a "lucky number": they decide every dice roll |

The code uses digits and letters, but not `I`, `L`, `O` and `U`, which are easily mistaken for `1`, `0` and `V`.

### Separate dice

Inside the program the "dice rolls" don't all come from one bag: there are several, each one made from the seed with a different label:

- one for the random **parameters** (how many levels, rooms, entrances, secrets);
- one for the dungeon **types**, when you don't choose them;
- one for the **story** and one for the **history text**;
- one for the **map**;
- one for the **monsters** and one for the **traps**, which are added afterwards, once the map is finished.

So if you change a sentence of the story in the JSON file, the map of the same seed stays identical; and choosing story, monsters and traps or not doesn't change the map (traps only add the `^` symbol on the game master's map).

### Random parameters

If you choose "fully random dungeon", the program rolls like this:

- **levels**: 1 to 6, with 2 and 3 the most likely (weights 2, 4, 4, 3, 1, 1);
- **rooms**: 5 to 10 per level, plus 0–3 more;
- **entrances**: 1 to 4, with 2 the most likely;
- **secrets**: from 1 to a fifth of the rooms.

The limits are: 1 to 10 levels, 5 to 200 rooms (at least 5 per level), 1 to 9 entrances, 0 to 60 secrets.

## 3. Dungeon types and how they stack

There are 11 dungeon types. Each has a letter (the one in the seed), a typical **floor plan** (chapter 6) and a list of types that may lie **below** it.

| Letter | Type | Above ground? | What may lie below |
|---|---|---|---|
| A | Palace | yes | palace, prison, tomb, temple, arcane laboratory, city, Underdark |
| B | Prison | no | prison, arcane laboratory, tomb, Underdark |
| C | Tower | yes | any type |
| D | Castle | yes | castle, prison, tomb, temple, arcane laboratory, city, Underdark |
| E | Temple | no | temple, tomb, prison, arcane laboratory, city, Underdark |
| F | City | no | city, tomb, prison, temple, arcane laboratory, Underdark |
| G | Arcane laboratory | no | arcane laboratory, prison, tomb, Underdark |
| H | Academy | yes | academy, temple, arcane laboratory, tomb, prison, city, Underdark |
| I | Border fortress | yes | fortress, prison, tomb, temple, Underdark |
| J | Tomb | no | tomb, Underdark |
| K | Underdark | no | Underdark only |

Examples:

- `CDK` is fine: a tower on top of a castle, the caves of the Underdark below the castle.
- `JD` is not: a castle cannot lie below a tomb. The program says so with an error message.
- `K` with 4 levels becomes `KKKK`: four levels of Underdark.

### When the program chooses the types

- 4 times out of 10 (and always with a single level) every level is of **the same type**.
- Otherwise it starts from a random type and goes down: each level, 4 times out of 10, is of the same type as the one above, otherwise one of the types allowed below it.

### The ground level

The **ground level** is where the main entrance is. It is the lowest of the levels built above ground (palace, tower, castle, academy, fortress). If there is none, it is the first level.

Example `CDK`: the tower (level 1) and the castle (level 2) are above ground. The lowest is the castle: main entrance **A** is on level 2, and the tower rises above the castle.

## 4. How many rooms per level

The rooms are shared out among the levels almost evenly, then a few random swaps are made, never going below 5 rooms per level.

### The sub-level

If there are enough rooms (at least 5 per level, plus 3), 3 rooms go into a **sub-level**: a small hideout halfway between two levels, called for example `2a` (between 2 and 3). With a single level, the sub-level lies below it.

Example `3-21-…`: 3 levels × 5 = 15, plus 3 makes 18, and 21 is more than 18. So 3 rooms go into sub-level `2a` and the other 18 are shared among the 3 levels: 6, 6 and 6, then the random swaps give 5, 5 and 8.

### The divided level

Some levels are **split into two halves** that don't touch: to go from one half to the other you must pass through another level. It is one of Jaquays' ideas, and it forces the players to explore vertically.

- Only a level with at least 6 rooms can be divided, and each half needs at least 3 (the least for a loop).
- At most one level in three, and never two divided levels one above the other.

On the map, the level heading says so: `LEVEL 3 · UNDERDARK · divided`.

## 5. The slot grid

Every level is a **grid of slots**, like a chessboard. Each slot is a rectangle of **24 × 11 letters** and can hold at most one room.

Why 24 × 11? Because letters are about **twice as tall as they are wide**: 24 letters across and 11 down make, on paper, an almost square box.

```
  slot (0,0)              slot (1,0)              slot (2,0)
 ┌────────────────────────┬────────────────────────┬────────────────────────┐
 │  ┌──────────────────┐  │                        │                        │
 │  │ at most 20 × 7   │  │      empty slot:       │                        │
 │  │ letters of       │  │      corridors         │                        │
 │  │ floor            │  │      run through it    │                        │
 │  └──────────────────┘  │                        │                        │
 └────────────────────────┴────────────────────────┴────────────────────────┘
```

- Inside a slot, a room leaves a 2-letter margin on every side: room for the walls and for the corridors to pass. The floor of a one-slot room is at most **20 × 7** letters.
- Big rooms (a courtyard, a nave, a plaza) take **several slots**.
- There are always some **empty slots**: about a third more than the number of rooms, plus one. The corridors run through them, and the map has room to breathe.

Example: 9 rooms → 9 + 4 + 1 = 14 slots → a grid of 4 columns × 4 rows (16 slots, 7 empty).

## 6. The floor plan of each type

Each dungeon type arranges its rooms on the grid in its own way. Here is how the program places **9 rooms** for each type. Key to the diagrams:

- `·` = empty slot;
- in CAPITALS the main rooms, which always belong to the founders (age I);
- `*` = **twin** room: the mirror image of the one on the other side of the axis;
- the other words give the shape (`room` rectangular, `round`, `octagon`, `small`, `wing`).

#### A Palace (palace) — 5 × 4 slots

    ·     | octagon  |   HALL   | octagon* |    ·
    ·     |   room   |   HALL   |  room*   |    ·
    ·     |   room   |    ·     |  room*   |    ·

   cell   |   cell   |   cell   |    ·     |    ·     |    ·

  round   |  round   |   CORE   |  round
    ·     |  round   |  round   |  round

```

What each plan does:

| Type | Plan | How it works |
|---|---|---|
| Palace | symmetric | A north-south axis; the throne **hall** in the middle; the other rooms in twin pairs left and right (sometimes octagonal); one room on the axis may become a **court**. |
| Prison | blocks | Rows of small **cells**, all alike and lined up; **guards** at the ends; with 12 rooms or more, a round **pit** in the middle. |
| Tower | radial | A round **core** in the middle and every other room round, packed around it. |
| Castle | ring | A big **courtyard** in the middle (even over several slots), the buildings all around; round **corner towers** and a **keep** on one side. |
| Temple | symmetric | The long **nave** on the axis, the round **apse** at its head, the side **chapels** in twin pairs. |
| City | blocks | A **plaza** in the middle (up to 2 × 2 slots), a **hall** nearby, scattered houses with streets between them. |
| Arcane laboratory | radial | A summoning **circle** in the middle, the octagonal **lab** next to it, rooms of different shapes. |
| Academy | ring | A **cloister** in the middle, the **library** and the **hall** on the outer ring, identical wings. |
| Border fortress | line | A long row: round **bastions** at the ends, the **keep** in the middle (as tall as the fortress), a **gate** at the bottom. |
| Tomb | processional | An axis: **antechamber** at the top, halls along the way, **burial** chamber at the end; small **niches** in twin pairs on both sides. |
| Underdark | scattered | Caves scattered everywhere; with 8 rooms or more, a **great cavern** over two slots. |

If a plan cannot fit on the grid (for instance with very few rooms), the program falls back on the scattered plan, which always works.

## 7. The ages: the strata of the dungeon

A good dungeon has a history, and the history shows in its walls. Every room belongs to one of four **ages**:

| Age | Tag | Who | Walls on the map |
|---|---|---|---|
| Natural | **N** | caves older than any building | `#` |
| First age | **I** | the founders | double `═ ║ ╔ ╗` |
| Second age | **II** | those who came after and refitted the halls | single `─ │ ┌ ┐` |
| Third age | **III** | today's dwellers, who dig roughly | `#` |

### How much each age weighs

Each type has its own weights. Some examples:

| Type | N | I | II | III |
|---|---|---|---|---|
| Tower | 0% | 75% | 25% | 0% |
| Castle | 0% | 60% | 30% | 10% |
| Tomb | 5% | 70% | 15% | 10% |
| Underdark | 75% | 10% | 10% | 5% |

### Ages come in patches

Ages aren't rolled room by room, or the map would look like a patchwork quilt. The program does this:

1. it scatters a few points on the grid (about one every three rooms), each with an age rolled with the type's weights;
2. every room takes the age of the **nearest point**.

So rooms of the same age stay close together, like wings added to a building at different times.

### The exceptions

- The main rooms (the throne hall, the nave, the courtyard, the burial chamber…) **always belong to the founders**.
- A twin room always has the same age as its twin.
- Every dungeon has at least one founders' room and **at least two different ages**.
- The rooms of a sub-level all belong to the second age, or are natural caves if the type has any.
- A corridor takes the age of the **younger** of the two rooms it joins: those who came later connected to the older works.

How shape and size are decided:

- **Natural caves** (N) are always ellipses with an uneven edge, made by adding three "waves" to the outline. The program keeps a single connected piece, so no islands of floor are left.
- **Third-age** rooms (III) that should have been rectangular become **rough**: corners chipped off at random and a few bulges along the sides.
- Big **main rooms** (halls, courtyards, naves…) take from 75% to 100% of the available space.
- **Founders'** rooms are from 40% to 100% of the slot wide: they built big.
- The others are smaller, up to about two thirds of the slot.
- **Round** rooms are twice as wide as they are tall, so on paper they really look round.
- Cells (`small`) are 5–7 × 2–3 letters and all centred, lined up as in a real cell block.
- **Twins** are the exact mirror copy of their room.

### Pillars and numbers

- The founders' big rectangular halls, if at least 10 letters wide and 5 tall, get **two rows of pillars** `■`, one every three letters, centred symmetrically.
- Every room gets a **number** of the form `level-number` (`1-01`, `2a-03`), written in the middle, in bold, on the game master's map only. Rooms are numbered in reading order: left to right, top to bottom.

### First step: who is next to whom

The program must decide which pairs of rooms are "neighbours". It uses a geometric rule called the **Gabriel graph**:

> Two rooms are neighbours if, drawing a circle with both of them on its edge, opposite each other, **no other room lies inside the circle**.

```
   A . . . . . . . . . B        A and B are not neighbours:
         .  C  .                C lies inside the circle between them.
                                A–C and C–B are neighbours instead.
```

This rule gives pairs of rooms that are really close, and corridors that don't cut across other rooms. Distances are measured taking into account that letters are twice as tall as they are wide.

### Second step: the tree

The program lines up the neighbouring pairs from the shortest to the longest and takes them one by one, **skipping those that join rooms already reachable**. The result is a **tree**: every room is connected, with the fewest corridors and no loops.

In the example: `1-06–1-05`, `1-01–1-03`, `1-03–1-04`, `1-03–1-05`, `1-03–1-02`. Five corridors for six rooms.

### Third step: the loops

A tree has a flaw: there is only one way to get from one room to another. So the program adds **loops**, corridors that close a circuit.

- The number of loops is a percentage of the rooms, different for each type: 25% for the tomb, 50% for the city, 30–40% for the others. In the example: 6 × 25% = 1.5, rounded to **2 loops**.
- Loops are picked at random among the neighbouring pairs left out of the tree, preferring the shortest.
- **Every part of every level has at least one loop**: even a 3-room sub-level, even each half of a divided level. If the chosen corridor cannot be dug, the program tries other pairs until one works.

### Doors

Every corridor starts at a door and ends at a door.

- The door goes on the wall facing the other room. If the room already has a door on that side, the program reuses it.
- In built rooms (ages I and II) doors sit **in the middle of a straight wall**, never in a corner.
- Two doors of the same room are never side by side.
- In built rooms, 3 doors out of 4 are real doors `+`; the others, and all those of caves, are plain openings `.`.

### Digging: the cheapest path

To dig the corridor between two doors, the program looks for the "cheapest" path with a method called **A\*** ("A star"), the one road navigators use too. Every step has a cost:

| Step | Cost | Effect |
|---|---|---|
| through rock | 1 | |
| along a corridor already dug | 0.6 | corridors merge and are reused, like roads |
| through rock but **next to** a corridor | +1.5 | no parallel corridors stuck together |
| every turn | +0.5 | straight corridors, with few turns |

Corridors never cross rooms or their walls, and in a divided level they stay in their own half.

## 10. Stairs, shafts, portals and sub-levels

After the corridors, the program connects the levels. The rules come from Jaquays' principles:

### Stairs between neighbouring levels

- Between two levels one above the other there are **at least 2 stairs**; if both have at least 8 rooms, 6 times out of 10 there are **3**.
- Each staircase uses **different rooms**: the two stairs between levels 1 and 2 don't start from the same room and don't end in the same room.
- The program always picks the **least used** room, so connections spread across the whole level.
- If a level is divided, each of its halves gets at least one staircase.
- On the map: `>` goes down, `<` goes up.

### Shafts that skip levels

With 3 levels or more there is a **shaft** or chimney `○` that skips one level (for instance from 1 to 3); 3 times out of 10, if there are enough levels, it skips two (from 1 to 4). With 6 levels or more there are two shafts. So players can "skip" part of the dungeon, or fall into it.

### The sub-level

The sub-level is reached by a **staircase** from the level above into its first room, and left by a **shaft** from its last room to the level below. It can be crossed, like a hidden shortcut.

### The magic portal

Sometimes a **portal** `Ω` joins two distant points: two levels at least two floors apart (with at least three levels), or two far-apart rooms of the same level (with a single level).

- The chance depends on the type: 100% in the arcane laboratory, 70% in the tower, 20–60% in the others. The highest among the dungeon's level types counts.
- The portal only appears with at least 15 rooms (8 for the arcane laboratory).

### Never the same pair twice

Two rooms joined by a staircase are not also joined by a shaft or a portal: every connection leads somewhere new.

  2-05   ↔ 3-03   stairs

  1-02   ↔ 3-08   shaft/chimney    ← skips level 2

  2a-03  ↔ 3-01   shaft/chimney    ← out of the sub-level

```

## 11. Entrances

Entrances are letters: **A**, **B**, **C**… (`I` is skipped, so it isn't mistaken for 1).

- **A**, the main entrance, is always on the **ground level** (chapter 3).
- **B**, if there are at least two levels, is a **midpoint entry**: on an underground level in the middle (or on one above ground, if there is nothing below). So players can come in "from the middle", another of Jaquays' principles.
- The other entrances go to the ground level 6 times out of 10, otherwise to a random level.

### How an entrance is dug

The program looks for a room close to the **edge** of the map and digs a **straight corridor** from one of its doors to the edge. On the map, outside the edge, the tag `[A]` appears in white on black.

- Entrances stay apart: at least 6 letters (2 if there is no other way).
- Each entrance uses a different room.
- An entrance corridor starting from a cave belongs to the third age: today's dwellers opened it.

If every edge is taken, the entrance becomes a **shaft from the surface** dropping straight into a room: the shaft `○` with the entrance letter next to it.

```
            [A]
            ║.║                ← entrance A: a straight corridor from the edge
            ║.║                  to the door of room 2-01
      ╔═════╩+╩═╗
     ╔╝....>....╚╗
```

## 13. Secret and unusual paths

The fourth number of the seed says how many **secrets** you want. The program shares them out like this:

1. **A third** become **secret passages**: a whole hidden corridor, drawn with `░` on the game master's map, with a secret door `$` at each end. Only a corridor not shared with others, at least 3 letters long, with doors used only by it, is chosen.
2. The others become **secret doors** `$` on visible corridors, **loops first**: so a secret is always a shortcut or an extra way, never the only road.
3. If you ask for more secrets than there are corridors, the program makes the other door of a corridor secret too, then **hides stairs and shafts** (portals last). If that's still not enough, it warns you with a message.

Then it adds the **unusual paths**, always on visible corridors and preferably on loops:

| What | Symbol | How many |
|---|---|---|
| **flooded** corridor | `≈≈≈` | 1 (2 with at least 40 rooms) |
| **cave-in** to climb over | `∴` | 1 (2 with at least 30 rooms) |
| **steps** on the same level | `≡≡` | 1 per level (2 with at least 8 rooms) |
| **pools** in caves | `≈` | in about 4 caves out of 10 |

Steps are a small **elevation shift**: the level isn't completely flat. If there is no straight stretch for two steps, one is enough; if there isn't even that, it becomes a dais in a room.

## 14. Checking Jaquays' principles

Before drawing, the program checks the dungeon and writes the result in the key (and shows it while working). For the tomb:

```
~ Multiple entrances: just one, as asked (loops and levels make up for it)
✓ Loops (cyclomatic number of the dungeon): 3; on each level: 1: 3
– Multiple level connections: not applicable (a single level)
– Discontinuous level connections: not applicable (a single level)
✓ Secret and unusual paths: 1 secret doors, 1 secret passages, 0 hidden stairs/shafts, 1 flooded, 1 cave-ins, 0 portals
– Sub-levels: not applicable (too few rooms per level)
– Divided levels: not applicable (a single level)
✓ Minor elevation shifts (steps on the same level): 1
– Midpoint entry: not applicable (a single level)
✓ Nested dungeons: the founders' work and later additions joined in 5 places
```

`✓` = done, `~` = partly done (because of your choice), `–` = not applicable, with the reason.

**The cyclomatic number**, put simply, is the number of independent loops: how many connections (corridors, stairs, shafts, portals, entrances) there are beyond the bare minimum needed to hold everything together. The tomb has 8 corridors and 1 entrance, that is 9 connections, among 7 points (6 rooms plus "the outside"): 9 − 7 + 1 = **3**. They are the 2 loops of chapter 9 plus the one added against dead ends. The higher the number, the more different roads there are.

**Nested dungeons** are parts of different ages or types that meet: natural caves joined to the built complex, or levels of different types linked by stairs, or (as here) the founders' rooms joined to those dug later.

## 15. From the grid to the drawing

Up to here the dungeon is a grid of numbers: rock, room floor, corridor, door. Now it becomes a drawing.

### The walls draw themselves

The program doesn't draw walls one by one: **every rock cell touching the floor** (diagonally too) becomes wall. Then it decides what it looks like:

1. it looks at the rooms next to it: if one belongs to the founders the wall is double, if it belongs to the second age it is single;
2. otherwise it looks at the corridors next to it;
3. if there are no built walls (caves, third age), the wall is `#`.

For double and single walls it picks the right piece (`═`, `║`, `╔`, `╩`, `╬`…) by looking at which neighbouring walls it joins to the north, east, south and west, like a tile game.

```
╔═════════╗    ┌─────────┐    ##########
║.........║    │.........│    #........##
║..1-01...║    │..1-02...│    #..1-03...#
║.........║    │.........│    ##.......##
╚═════════╝    └─────────┘     #########
founders (I)   second (II)    cave or third age (N, III)
```

## 16. From the drawing to the sheet

### The page

The page has: the dungeon's name (if you want one), a line with seed and numbers, the levels arranged in a grid and the **legend**. The legend lists only the symbols that actually appear, plus the **scale** (1 square = 5 ft or 1.5 m, as you chose).

The program tries every possible arrangement of the levels (1 column, 2 columns, 3…) and, for each paper size (A4, A3, A2, A1), picks the one with the **biggest letters**; when they tie, the one that fills the sheet best. It tries the sheet both portrait and landscape.

### Letter size

| Letters | Verdict |
|---|---|
| at least 1.3 mm | readable |
| between 1.1 and 1.3 mm | small |
| below 1.1 mm | too small |

The program suggests the smallest sheet with readable letters and shows all the alternatives; letters never exceed 3.2 mm on an A4 (more on bigger sheets). With "one level per sheet", every sheet uses the same letter size, so the maps match.

### The files

- **PNG** at 600 dpi or **PDF** (one page per sheet), in one of three colour schemes.
- A **.txt** with the same characters as the map, to open in any editor.
- The players' map has the same layout and the same letter size as the game master's.

## 18. What you can change in the JSON file

The `wyrmdelve_tables.json` file holds mostly words, but each dungeon type also has a few numbers that change the map:

| Field | What it changes | Example |
|---|---|---|
| `pattern` | the floor plan (chapter 6): `palace`, `prison`, `tower`, `castle`, `temple`, `city`, `wizard`, `academy`, `fortress`, `tomb`, `underdark` | a "temple" with `"pattern": "tomb"` gets a tomb's plan |
| `eras` | the weights of the four ages N, I, II, III | `[0.75, 0.1, 0.1, 0.05]` = mostly caves |
| `loops` | the share of loops | `0.5` = one loop every two rooms |
| `portal` | the chance of a portal | `1.0` = always |
| `below` | the types that may lie below | `["tomb", "underdark"]` |
| `surface` | whether the type stands above ground | `true` / `false` |

Careful: if you change these numbers, **the same seed will give a different map** than before. Words instead (room names, story, entrances…) only change the texts.
